# model-of-me — the operator's explicit model, versioned

Falsifiable beliefs about how you and the system behave. Revise on evidence;
keep history. A model that only accumulates caveats and does not remove beliefs
is a story, not a model.

---

## Worked example — fictional operator, v0.3

This example is illustrative; it is not maintainer data or repository history.

**Operating beliefs (each falsifiable, each with the evidence I'd accept against it):**
- Late-session judgment is my weakest gate: predictions logged after 22:00 score ~15 points worse than morning ones. (12-row sample; recheck at 30.)
- My ATTACK passes share a default frame (economics-first). For me, a useful check must name the pricing error it could expose, not just switch models.
- I snap-close on tasks that flatter an existing plan and go stuck-open on tasks that threaten one. The direction of my error follows the stakes, not the difficulty.
- Bare-test status: not internalized. This example's bare run skipped PREDICT; performance is system-dependent at this stage.

**Version history (believed → broke → changed):**
- v0.1 → v0.2: the operator believed "more context in the prompt = better output." That broke when RUN passes stayed invariant under a frame half the length. Changed to: context helps until it substitutes for a frame.
- v0.2 → v0.3: the operator believed "I'm a snap-closer, period." That broke when the example log showed three stuck-open weeks on the pricing question. Changed to: closure style is stakes-dependent — see belief 3.
