# PREDICT — no output before you commit

**The problem.** Without a prior expectation, the operator can read the answer
and feel as if they knew it already. The session produces output, but no error
signal.

**The rule.** Before the model reveals a deep-work result, require a
falsifiable commitment. It can be a predicted result, expected main factor,
which version will survive a check, expected direction of change, or numeric
probability when the event can calibrate future judgment. Confidence is
required only when it carries calibration value. Append the row to
[`state/predictions.log`](../state/predictions.log) as OPEN before output.
When the outcome is known, update only its status and note; the commitment
and scale do not change.

**Skipped, it fails as:** agreement after the fact. The operator updates the
story of what they expected instead of registering the miss.

**Failure pattern** *(canon: [`ENGINE`](../docs/ENGINE.md) §3 — safe
commitments)*. Commitments so broad they cannot miss, or numbers attached to
questions that do not support calibration.
**The test:** can this row be wrong in a way the operator would accept? If not,
rewrite it before output.

**Engine line.** The useful unit is a committed expectation that can meet a
later observation. → [`docs/ENGINE.md`](../docs/ENGINE.md)
